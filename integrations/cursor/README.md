```sh

A public source push does not by itself request this workflow; separately approve any dispatch/usage. Adding automatic push/PR triggers requires an explicit later decision. It runs those explicit phases when dispatched. It records the actual OS/architecture/Python. A saved workflow and local runner success are not a completed GitHub CI run; running it after a push/dispatch needs the existing Git/usage authorization. macOS CI is not native Cursor acceptance, and no native Windows/Linux support is advertised.

## Standalone helper delivery build

`scripts/cursor_delivery.py build --source ABS_REPOSITORY --native-archive ABS_ADVISORY_ZIP --native-sha256 TRUSTED_HEX --output FRESH_DIRECTORY` builds the separate fixed allowlist. `verify ZIP --sha256 TRUSTED_OUTER_HEX` checks its full inventory/manifest and pinned inner archive; `extract ZIP --sha256 TRUSTED_OUTER_HEX --dest FRESH_ABSOLUTE_DIRECTORY` verifies before anchored no-follow writes. A recipient must authenticate the outer checksum through a trusted channel before executing bundled code. Hashes are not publisher signatures. Existing or linked output destinations and normal profiles are refused; partial failed output needs review, not force cleanup.
