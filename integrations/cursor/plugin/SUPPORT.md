## First local checks

Use [README.md](README.md) in Terminal, outside agent chat. Confirm the exact trusted archive/checksum and complete helper closure before executing code. Use an unopened approved workspace and separate canonical external runtime/native-tools paths. Existing or linked control trees, malformed/duplicate JSON and unknown/modified ownership are refused; do not overwrite them or edit the ledger to force success.

- Workspace `health` checks source/configuration. Only explicit `--check-runtime` invokes local synthetic SDK probes. A requested unavailable runtime is nonzero even if configuration is ready.
- Runtime `doctor --dest ABS_RUNTIME` checks the external environment. It does not attest a running GUI's environment, trust, hook execution or a downstream block. The tag `0.1.0-preview.1-sdk0.1.9` intentionally remains independent of package version; a matching name alone is not proof of compatibility.
- Installation stages one project `workspaceOpen` entry; later workspace opening/reload can activate it. Do not launch a normal profile, change managed policy or send a prompt just to make support checks pass.
- Close the owned process before workspace removal. It preserves unrelated hooks/mode and the external runtime. Use retained verified native-tools for the later separate runtime doctor/remove; do not call a script already deleted with the project copy.
- Modified/concurrent/partial state needs local inspection with matching tools. No force cleanup, broad deletion, profile removal or automatic runtime migration is provided.

This delivery is advisory by default: a finding or unavailable check requests continuation. The prompt hook does not rewrite prompts. Ordinary chat cannot test automatic PII masking; use explicit Terminal `prepare`, inspect `[PII]` output and treat any later `--open`/review/Cancel as a separate editor action. A scanner finding, requested cancellation and observed downstream block are separate results. Use synthetic examples only; a free/trial account is not proof of zero submission charges.

On macOS, choose a short canonical user-data path: IPC socket path limits can reject an otherwise valid directory before workspace loading. Directory validation alone does not guarantee that the host socket path fits.

For editor review, all of `--open --user-data-dir ABS --extensions-dir ABS --cursor-profile NAME` are required. Use the existing canonical approved isolated directories and review the intended empty workspace first. Bare/partial open options, normal-profile roots and unsafe paths are refused. The fixed installed desktop CLI gets only accepted checked text and a minimal environment; no OS-opener/default-profile fallback. Named-build `--open-url` compatibility is not a guarantee across versions or of the exact window/workspace. Cancel on a wrong destination. Error/timeout can occur after handoff: inspect before a manual retry; do not automatically retry or send to prove success.

There is no automatic collector, telemetry exporter or upload command. Fill the template manually, substitute `<workspace>`, `<bundle>`, `<runtime>` and `<native-tools>` for personal paths, and review the entire message before sending. Share only information needed for this request.

```text
Artifact: native/helper version and trusted checksum
Platform: Cursor build/commit, OS/architecture, Python/uv/SDK versions
Step: plan / install / health / explicit runtime doctor / remove
Result: exit code, fixed status/reason/finding codes only
Configuration/runtime: ready / unavailable / not checked
Native loading/unload: observed / not observed, exact boundary named
GUI runtime consumption: observed / not observed
Reproduction: command shape with placeholder paths and fictional input
Expected versus actual metadata outcome
Unrelated configuration/runtime preservation: yes / no / unknown
```

Do **not** send raw prompts, source code, Hook Input/Output or native debug logs, provider transcripts, matched secrets/PII, account/user emails, session/conversation IDs, environment dumps, tokens or credentials. GuardTrellis's content-free diagnostics do not sanitize other logs/screenshots. Native host debug logs can retain event input. A support request does not authorize a model/provider test, account change, wider data collection or contact with others.
