Publisher: Sahil Mathur. Updated **30 October 2026** for the experimental native/delivery **0.1.0-preview.4** candidate with SDK **0.1.9**. This describes the native source, project helper, local runtime and explicit Terminal preparation. It is separate from the older integration skill/tester distributions. This native policy applies to the source, workspace helper, external runtime and manual support for this preview. Older website policies cover their own offerings; this file does not update them. No deployment or listing follows from this documentation change.

## Local inputs and purpose

The workspace helper reads the explicitly selected hook configuration, approved source archive and its own bounded ownership inventory. It stages one lifecycle entry plus a fixed source/control tree; it does not scan arbitrary application files or collect a workspace transcript. Its ownership record contains local workspace/runtime/Python paths and source/configuration hashes.

The `workspaceOpen` bootstrap receives a Cursor event through stdin. Host-supplied metadata can include workspace roots, host version and user-email metadata. It validates the exact selected workspace, record hash, owned entry and source inventory before returning a fixed plugin path. It does not call the SDK or retain a raw event payload. GuardTrellis failure output uses fixed status/reason fields. Cursor's own debug logs can retain the event independently.

When invoked, the prompt adapter reads a bounded JSON event and checks only its submitted prompt using selected SDK signatures; reading event bytes does not establish attachment/history coverage. It processes text locally, but actual preview.4 native prompt execution and outcomes remain unverified. Do not supply real credentials or unnecessary personal data to a demonstration.

The separate Terminal preparation command reads plaintext stdin, checks selected secrets first and masks selected email/contiguous-phone shapes. It intentionally emits reviewed remaining text to stdout and fixed metadata to stderr. Names, unsupported formats and other context can remain. A secret/error/unavailable result withholds deliverable text.

## Recipients and network boundaries

These local helper/scanner tools contain no publisher account system, hosted scanner, remote logger, analytics or automatic support collector. They do not upload checked payloads to the publisher. Explicit runtime setup can fetch locked dependencies from PyPI/distribution hosts, which receive ordinary request metadata under their policies. A trusted existing Python and explicit external environment are required; prompt handling never installs dependencies.

An explicit `prepare --open` additionally requires selected existing canonical user-data/extensions directories and a named profile. It passes accepted checked text as a local prompt deeplink argument to the fixed installed Cursor desktop CLI with a minimal environment; inherited remote/IPC routing and Node overrides are omitted. The host, OS/process inspection or tools may retain the checked text/URI and selected paths. Terminal history/scrollback, redirected output and manually created files can also retain text; local preparation does not erase those copies. This is not encrypted transient transport or proof that all remaining personal information was masked.

The selected directories/profile request the destination; they do not guarantee the precise workspace/window. This action may launch Cursor, opens review but never presses Send, and has no unscoped default-profile fallback. Inspect the destination and attachments/context; the redacted text does not sanitize other attached data. A failure/timeout can occur after handoff, so no automatic retry occurs and a failure does not prove that nothing opened. The accepted preview.4 runtime’s actual product path was observed through masked review and automated Escape/empty input in the named isolated host. This documentation-only refresh has new checksums and is not itself a whole-package host trial; submitted-prompt behavior and provider suppression remain unverified. Prior callback evidence remains separate.

Cursor, agent hosts and model providers can receive and retain task context, prompts, history and tool output under their own settings/terms. Cursor may process prompt text for naming before the selected hook. Local scanning, an advisory decision or Cancel does not establish no network traffic, no provider retention or complete prompt-egress prevention. The companion does not change those controls or automatically intercept other agents/tools.

## Local storage and removal

`<workspace>/.guardtrellis-cursor/` stores source, bootstrap and a hash-bound installation record. `.cursor/hooks.json` contains the derived command/path/hash entry. The external runtime has its own completion marker, source fingerprints and file inventory. The runtime marker/default identity intentionally remains `0.1.0-preview.1-sdk0.1.9`; a documentation version change does not migrate or authenticate an environment.

Copied source, prepared environments, synthetic test artifacts and host-captured streams remain locally until you remove them. The workspace helper preserves unrelated hooks and its external runtime. Runtime removal is a separate explicit owned-record operation using retained verified tools. Unknown or modified state is refused for review. Close the owned process before removal; a fresh authorized native observation is needed to establish unload. Removing local files does not delete host/provider history or backups.

Ownership hashes are local integrity metadata, not publisher signatures or protection against someone able to replace the installation code and configuration together. Separate profiles/user-data directories do not hide all OS-home hooks/caches or override managed policy.

## Support data handling

Contacting support is optional. If you do, the publisher receives your sender/contact address, message, the reviewed metadata you supply and any unsolicited attachments. These are used to answer the request, investigate an issue, coordinate a fix and meet applicable support, security and reporting duties. Email and other communication providers handle delivery/storage under their own policies. No automatic exporter or telemetry collector sends this information.

The publisher may share only the minimum necessary case, version, impact and contact details with Cursor for marketplace/security coordination, and with advisers or authorities where needed for applicable obligations. Reports are not sold or used by the publisher to train models. An accidentally supplied secret or private payload should not be resent: access is restricted, unnecessary copies are removed, and only the minimum evidence needed for an incident or applicable obligation is retained. A synthetic replacement may be requested; complete raw reports are not routinely forwarded.

Retention is purpose-based, with no fixed retention period: review records at case closure and when continuing support/security/reporting purposes end, remove unnecessary attachments and working copies, and retain only what remains needed for those purposes or applicable obligations. Deletion from the publisher's active records cannot promise immediate erasure from provider backups, delivery systems, your own copies or Cursor/provider history.
